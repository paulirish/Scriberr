# Guide to Extracting Python Adapter Scripts

This guide explains how to extract inline Python scripts and configuration files from Go adapters into separate source files, using the `embed` package to bundle them.

## 1. Create a Scripts Directory

Create a directory to hold the scripts corresponding to the adapter.
Standard location: `internal/transcription/adapters/py/adapters/<adapter_name>`

```bash
mkdir -p internal/transcription/adapters/py/adapters/<adapter_name>
```

## 2. Extract Files

Copy the inline content from the Go file into separate files in the new directory.

*   `transcribe.py`: The main transcription script.
*   `pyproject.toml`: The dependency configuration (if using `uv` or similar).
*   Any other scripts (e.g., `transcribe_buffered.py`).

## 3. Update the Go Adapter

### Import `embed`

Add the `embed` package to the imports.

```go
import (
    "embed"
    // ... other imports
)
```

### Embed the Scripts

Add the `//go:embed` directive and a variable to hold the file system. This should be at the package level.

```go
//go:embed py/adapters/<adapter_name>/*
var <adapterName>Scripts embed.FS
```

**Note:** The path in `//go:embed` is relative to the Go file.

### Read Embedded Files

Replace the inline strings with calls to `ReadFile`.

**Before:**
```go
scriptContent := `... inline python code ...`
scriptPath := filepath.Join(p.envPath, "transcribe.py")
if err := os.WriteFile(scriptPath, []byte(scriptContent), 0755); err != nil { ... }
```

**After:**
```go
scriptContent, err := <adapterName>Scripts.ReadFile("py/adapters/<adapter_name>/transcribe.py")
if err != nil {
    return fmt.Errorf("failed to read embedded transcribe.py: %w", err)
}

scriptPath := filepath.Join(p.envPath, "transcribe.py")
if err := os.WriteFile(scriptPath, scriptContent, 0755); err != nil { ... }
```

Repeat this for all extracted files (`pyproject.toml`, etc.).

## 4. Update .gitignore

Ensure that Python artifacts are ignored.

```gitignore
# Python
__pycache__/
*.py[cod]
*$py.class
```

## 5. Verify

Run the application or tests to ensure the adapter still functions correctly. The files should be written to the runtime environment path (e.g., `data/<adapter>-env`) just as they were before.

# How it Works (Under the Hood)

This section explains the mechanics of how the Go application interacts with the Python scripts, the role of `uv`, and the file structure.

### Runtime Execution Flow

1.  **Initialization (`PrepareEnvironment`):**
    *   The Go adapter reads the embedded files (`transcribe.py`, `pyproject.toml`, etc.) from the compiled Go binary.
    *   It writes these files to a dedicated runtime directory, typically located at `data/<adapter>-env` (relative to the application execution root).
    *   It executes `uv sync` in this directory. `uv` reads the `pyproject.toml` and creates a Python virtual environment (`.venv`) within that directory, installing all necessary dependencies.

2.  **Invocation (`Transcribe`):**
    *   When a transcription request is received, the Go adapter constructs a command to run the Python script.
    *   It uses `uv run` to execute the script within the context of the managed environment.
    *   **Command Structure:**
        ```bash
        uv run --native-tls --project <runtime_env_path> python <script_path> [arguments]
        ```
    *   `--project <runtime_env_path>` tells `uv` to use the environment and configuration found in the specific adapter's runtime folder.

### Key Components

*   **`uv`:** A fast Python package installer and resolver. It manages the virtual environment and dependencies for each adapter independently. This ensures that adapters with conflicting dependencies (e.g., different versions of `torch` or `numpy`) can coexist without issues.
*   **`pyproject.toml`:** The standard configuration file for Python projects. It defines the dependencies required for the specific adapter. `uv` uses this to strictly lock versions and ensure reproducibility.

### Directory Structure

There is a clear separation between the **Source Code** (where you edit files) and the **Runtime Environment** (where the app runs them).

#### Source Location (In Git)
Where you develop and commit changes.
```text
internal/transcription/adapters/py/adapters/
└── <adapter_name>/
    ├── pyproject.toml       # Dependency definitions
    ├── transcribe.py        # Main logic
    └── other_scripts.py     # Helper scripts
```

**Note:** The `py/` directory is located within the `adapters` package to satisfy Go's `embed` directive requirements, which cannot reference parent directories. All Python source files live here and are version-controlled, making them easily lintable and testable.

#### Runtime Location (On Disk)
Where the application sets up the environment during execution.
```text
data/
└── <adapter>-env/
    ├── .venv/               # Virtual environment created by uv
    ├── uv.lock              # Lockfile generated by uv
    ├── pyproject.toml       # Copied from source
    ├── transcribe.py        # Copied from source
    └── ...
```
